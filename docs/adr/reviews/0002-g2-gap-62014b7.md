## Cross-cutting findings

1. The baseline's "all authorization records are flat" finding no longer holds. `shared/src/authz_record.rs:23-33,265-289,364-478` provides exact closed DeviceApproval, CapabilityGrant, DeviceHpkeGrant and three-variant RootGrant records with correct domains, hashes, strict signatures and time ordering. D1 approval and gen-0 root bootstrap/read/ACK/activate persist those records with ledger and audit in transactions. General device approval, root issuance, rotation and revocation are unfinished.
2. Two protocol generations coexist: legacy fleet grants and manifests still pass through `server/src/authz.rs:19-33,206-347` and `server/src/routes/v2.rs:581-582,944-945`. Passing shared tests therefore do not prove end-to-end custody.
3. ADR 0003 is the suite-2 object contract, not an integration claim. `shared/src/envelope_v2.rs:474-604` verifies the expected object/preamble/intent/slot hashes before decrypting; callers must authenticate the manifest first and stage/discard partial output on error. No launcher or server use of `envelope_v2` was found. Legacy restore buffers until signature/head checks finish and checks the requested profile (`shared/src/backup_file.rs:299-318`).
4. Fleet keys from the server are counted, never opened or cached (`src-tauri/src/fleet_keys.rs:24`, regression `src-tauri/src/lib.rs:2584`); push seals with the team passphrase (`src-tauri/src/sync_cmd.rs:310`). This removes the baseline's insecure fleet-key consumption path but is not verified fleet distribution. Legacy cached keys are a documented compatibility limit (`docs/trust-boundaries.md:60-68`).
5. All eleven local persistence probes (G2-33..G2-43) are MISSING: the launcher stores team JSON (`src-tauri/src/team_config.rs:263-308`), and a scoped search for `recovery_journal|schema_meta|min_reader_version|migration_state|PRE_V2_RESTORE|v2_local_|tombstone` in production code found nothing.
6. Restore is designed, not implemented. ADR 0002 D-1 requires the G2 fixture harness for the restore crash rows while production restore stays refused (`docs/adr/0002-g2-contract-decisions.md:309-315`; `server/src/identity.rs:259-260`). G2-55/56/57/60 therefore move DESIGN-OPEN -> MISSING.
7. Accepted ADR decisions are used as the contract where they settle earlier design-open questions, but are not counted as implementation.

## Real defects found

Both were source-traced at 62014b7 and are **fixed in #156** (merged as `d48d85c` on `team-custody-production`), each with a regression test.

1. **A repeated open-upload truncated already-staged bytes before the duplicate was refused** (G2-23). `server/src/fleet.rs:284-313` created/truncated the deterministic staging file before the INSERT failed on the existing session key. Sequence: open session S (declared size 3), append `abc`, repeat the identical open request. The staging file became empty while the row kept `received_size = 3`, so the commit could no longer match. Inherited from 439e932. Fix: insert the session row first, then truncate; delete the row if truncation fails. Test `reopening_a_session_keeps_its_staged_bytes`.
2. **A negative `key_generation` passed the signed-field equality check** (G2-45). `server/src/routes/v2.rs:604` compared the signed value with `req.key_generation.max(0) as u64`, so `-1` matched a signed `0`. The blob was promoted (`server/src/fleet.rs:495`) and the INSERT then hit the CHECK at `server/migrations/0004_v2_team_fleet.sql:281`, returning 500 after a filesystem side effect. The same clamp on `base_version` (`:601`) was only stopped later by the head-version check. Fix: checked `u64::try_from` for both fields, rejecting with 400 before any side effect. The `v2_e2e` commit test now sends `-1` for each field first.

No other defect is asserted. Missing gate coverage and legacy compatibility limits are recorded in the table, not here. The shared object API's partial output on a later frame error is documented caller behaviour (stage and discard), not a defect.
